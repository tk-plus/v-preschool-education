# 数据库设计（初稿）

对应[小程序产品方案](./小程序产品方案.md)。使用 MySQL；一个微信账号对应一份学习记录。本文先定义逻辑结构，建表 SQL 在开发时用 Flyway 迁移文件落实。

## 统一约定

- 主键统一为 `BIGINT` 类型的 `id`；外键字段命名为 `xxx_id`。
- 金额以“分”存为 `BIGINT`，不使用浮点数。时间使用 `DATETIME(3)`，业务层统一按北京时间计算周榜边界。
- 大多数表包含 `created_at`、`updated_at`；内容表增加 `status`。订单、答题记录不做物理删除。
- 微信 `openid`、管理员密码摘要和支付凭据属于敏感数据；服务端保存，接口不返回给小程序。数据库不对公网开放。
- `module_id` 表示所属模块。新增唐诗、英语等模块时，优先复用通用答题与权益表，模块特有内容放在题目数据字段或专用扩展表。

## 一、账号与模块

### 1. `app_user`：微信用户

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 用户编号，主键 |
| `openid` | VARCHAR(64) | 小程序内唯一微信标识，唯一索引 |
| `public_name` | VARCHAR(32) | 排行榜展示名称，默认匿名名称 |
| `ranking_opt_in` | TINYINT | 是否参与公开排行榜，默认否 |
| `status` | VARCHAR(16) | 正常、禁用 |
| `last_login_at` | DATETIME(3) | 最近登录时间 |
| `created_at`, `updated_at` | DATETIME(3) | 创建、更新时间 |

不要求孩子提供真实姓名、生日或手机号。家长管理的微信账号即购买账号和学习账号。

### 2. `admin_user`：管理端账号

`id`、`username`（唯一）、`password_hash`、`role`、`status`、`last_login_at`、`created_at`、`updated_at`。管理员登录与微信用户登录使用不同的身份校验。

### 3. `learning_module`：学习模块

`id`、`code`（唯一，如 `idiom`）、`name`、`description`、`cover_url`、`sort_order`、`is_standard`（是否被全模块权益覆盖）、`status`、`created_at`、`updated_at`。

## 二、题库与关卡

### 4. `question`：题目

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 题目编号 |
| `module_id` | BIGINT | 所属模块 |
| `question_type` | VARCHAR(32) | 如 `shared_character_pool`、`poem_blank` |
| `source_text` | VARCHAR(255) | 完整成语或诗句，如“兴高采烈” |
| `prompt_text` | VARCHAR(255) | 答题前文字，如“兴高□烈” |
| `prompt_pinyin` | VARCHAR(255) | 答题前拼音，缺字位置留空 |
| `full_pinyin` | VARCHAR(255) | 答题后完整拼音 |
| `blank_index` | SMALLINT | 缺字位置；复杂题型可不用 |
| `answer_text` | VARCHAR(64) | 正确缺字，如“采”；其他模块可存较长答案 |
| `meaning` | TEXT | 简短释义、讲解 |
| `hint_text` | VARCHAR(255) | 第一层释义提示 |
| `hint_pinyin` | VARCHAR(64) | 第二层缺字拼音提示 |
| `audio_prompt_url` | VARCHAR(512) | 答题前不泄露答案的朗读音频 |
| `audio_full_url` | VARCHAR(512) | 答题后完整朗读音频 |
| `difficulty` | TINYINT | 难度级别 |
| `version` | INT | 题目发布版本，初始为 1 |
| `content_json` | JSON | 特定题型的附加内容，如配图、英语释义 |
| `status` | VARCHAR(16) | 草稿、待审核、已发布、停用 |
| `reviewed_by`, `reviewed_at` | BIGINT、DATETIME(3) | 审核人和审核时间 |
| `created_at`, `updated_at` | DATETIME(3) | 创建、更新时间 |

同一成语如果有不同缺字位置，应建为不同题目；可用 `source_text` 汇总到同一成语。发布前人工校对答案、拼音、释义和音频。上线后若改动题目，应保留历史作答所依据的题目版本，避免旧记录被新答案误判；第一版可用 `version` 字段及发布后复制新题的方式处理。

成语填字不使用每题 A/B/C/D 选项。一个答题屏幕中多个成语共用 10 个字块，字块由后台按本屏题目生成并保存为回合快照。每个缺字应有可用字块，若不同题目的正确字相同，应生成足够数量的同字字块。

### 5. `level`：关卡

`id`、`module_id`、`level_no`、`title`、`level_type`（普通/阶段复习）、`is_free`、`status`、`created_at`、`updated_at`。普通关卡唯一约束 `(module_id, level_no)`。每 10 个普通关卡开放一个阶段复习关；复习关题目按用户错题动态生成。

### 6. `level_question`：普通关卡与新题的关系

`id`、`level_id`、`question_id`、`sort_order`。唯一约束 `(level_id, question_id)`。成语模块每个普通关卡配置 3 道新题；到期错题另起一屏复习，不写入此表。

## 三、购买、支付与权益

### 7. `product`：可购买商品

`id`、`name`、`scope_type`（`MODULE`/`ALL_STANDARD`）、`module_id`（全模块商品为空）、`price_cent`、`valid_days`（永久权益为空）、`status`、`created_at`、`updated_at`。订单创建时必须复制商品名称、价格和期限快照，避免事后改价影响历史订单。

### 8. `purchase_order`：购买订单

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键 |
| `order_no` | VARCHAR(64) | 系统订单号，唯一 |
| `user_id`, `product_id` | BIGINT | 买家、商品 |
| `product_name_snapshot` | VARCHAR(128) | 下单时的商品名 |
| `scope_type_snapshot` | VARCHAR(32) | 下单时的权益范围 |
| `module_id_snapshot` | BIGINT | 单模块商品对应模块 |
| `valid_days_snapshot` | INT | 下单时的有效期 |
| `original_amount_cent` | BIGINT | 原价 |
| `discount_amount_cent` | BIGINT | 升级抵扣等优惠，默认 0 |
| `pay_amount_cent` | BIGINT | 实付金额 |
| `status` | VARCHAR(20) | 待支付、已支付、已关闭、退款中、已退款 |
| `provider_order_no` | VARCHAR(128) | 微信侧订单号，唯一或为空 |
| `paid_at`, `closed_at` | DATETIME(3) | 支付、关闭时间 |
| `created_at`, `updated_at` | DATETIME(3) | 创建、更新时间 |

支付结果由后台通过微信回调及必要的主动查询确认，不能相信小程序前端传来的“支付成功”。升级抵扣的具体规则确定后再增加关联旧权益的字段或独立抵扣记录表。

### 9. `payment_event`：支付通知与处理记录

`id`、`event_id`（微信通知唯一标识，唯一）、`order_id`、`event_type`、`provider_status`、`received_at`、`processed_at`、`process_status`、`error_message`。验签后记录通知并幂等处理；敏感原始报文不长期明文保存。

### 10. `user_entitlement`：用户权益

`id`、`user_id`、`source_order_id`（唯一，防止同一订单重复开通）、`scope_type`、`module_id`、`starts_at`、`expires_at`（永久为空）、`status`（生效/撤销/过期）、`revoked_at`、`created_at`、`updated_at`。全模块权益实时覆盖 `learning_module.is_standard=1` 的已上架模块。

### 11. `refund_order`：退款记录

`id`、`refund_no`（唯一）、`order_id`、`provider_refund_no`、`amount_cent`、`reason`、`status`、`requested_at`、`completed_at`。退款成功后按规则调整权益；部分退款如何处理需在售卖规则确定后落实。

## 四、闯关、错题与学习记录

### 12. `answer_session`：一次答题回合

`id`、`user_id`、`module_id`、`session_type`（普通关/阶段复习/周挑战）、`level_id`（周挑战时为空）、`challenge_id`（非周挑战时为空）、`status`、`started_at`、`submitted_at`、`duration_ms`。后端创建回合时固定本次题目与字块清单，避免刷新页面导致内容变动。

### 13. `session_round`：回合中的一屏题目

`id`、`session_id`、`round_no`、`round_type`（新题/错题/挑战题）、`status`、`created_at`。唯一约束 `(session_id, round_no)`。普通关卡第一屏为 3 道新题；有到期错题时追加复习屏。每屏最多 3 道成语，共用 10 个字块。

### 14. `round_tile`：一屏共用字块

`id`、`round_id`、`tile_no`、`character_text`、`pinyin`、`created_at`。唯一约束 `(round_id, tile_no)`。每屏固定 10 个字块；相同汉字可以出现多个字块。字块顺序和内容在回合创建时保存，刷新后保持一致。正确字、干扰字及拼音由后台校对或生成。

### 15. `session_question`：本回合题目清单及作答

`id`、`session_id`、`round_id`、`question_id`、`sort_order`、`source_type`（新题/错题/挑战题）、`selected_tile_id`、`selected_text_snapshot`、`question_version`、`is_correct`、`hint_count`、`answered_at`、`answer_duration_ms`。唯一约束 `(session_id, question_id)`；正确与否由后台根据题目正确缺字和所选字块计算。提交前允许撤回和更换字块，最终作答才写入成绩。一个字块同一屏只能占用一个空位。

### 16. `user_level_progress`：关卡进度

`id`、`user_id`、`level_id`、`first_completed_at`、`best_correct_count`、`last_session_id`、`updated_at`。唯一约束 `(user_id, level_id)`。

### 17. `user_question_mastery`：个人错题与掌握状态

`id`、`user_id`、`question_id`、`wrong_count`、`review_step`、`consecutive_review_correct`、`mastery_status`（待复习/已掌握）、`next_review_level_no`、`last_seen_level_no`、`last_answered_at`、`updated_at`。唯一约束 `(user_id, question_id)`。答错后安排在约第 2、5、10 个后续关卡复现；跨不同关卡连续复习答对 2 次后标记为已掌握。

## 五、每周挑战与排行榜

### 18. `weekly_challenge`：模块周挑战

`id`、`module_id`、`week_start_date`（北京时间周一日期）、`status`、`created_at`。唯一约束 `(module_id, week_start_date)`。

### 19. `weekly_challenge_question`：统一挑战题

`id`、`challenge_id`、`question_id`、`sort_order`。唯一约束 `(challenge_id, question_id)`；每个模块每周约 10 题，分多屏展示，每屏最多 3 题并各有 10 个共用字块。挑战发布时固定每屏字块内容和顺序，所有参赛账号看到同一套题与字块；可将各屏配置存入 `weekly_challenge.round_config_json`。发布后本周不再改题。

### 20. `weekly_challenge_result`：用户周成绩

`id`、`challenge_id`、`user_id`、`session_id`、`correct_count`、`duration_ms`、`submitted_at`、`is_valid`。唯一约束 `(challenge_id, user_id)`，只记录该账号本周首次完整挑战的成绩。榜单按 `correct_count DESC, duration_ms ASC, submitted_at ASC, id ASC` 排序，取前十；未同意公开的账号不进入公开榜，但可查看自己的成绩。

## 六、后台审计

### 21. `admin_audit_log`：管理操作日志

`id`、`admin_user_id`、`action`、`target_type`、`target_id`、`detail_json`、`created_at`。记录题目审核、商品改价、权益调整、成绩作废和退款处理等重要操作。

## 关键关系与实现顺序

```text
app_user ──< purchase_order ──< payment_event
    │                │
    │                └─────── user_entitlement
    ├──────< answer_session ──< session_round ──< round_tile
    │                └────────< session_question >── question
    ├──────< user_level_progress >── level ──< level_question >── question
    ├──────< user_question_mastery >── question
    └──────< weekly_challenge_result >── weekly_challenge

learning_module ──< level / question / weekly_challenge / product
```

建议按以下顺序建表和开发：账号与模块 → 题库与关卡 → 答题及错题复习 → 周榜 → 商品、订单、支付与权益 → 管理审计。支付能力准入和接口以申请时微信官方文档为准。
